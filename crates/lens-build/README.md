# `lens-build`

High-performance compilation database (`compile_commands.json`) parser, compiler flag normalizer, header include dependency DAG engine, and reverse compilation impact analyzer.

## Overview

`lens-build` is the modernized Rust replacement for `buildscope`. It processes Clang / GCC compilation databases produced by CMake, Meson, Bear, or Ninja, extracts preprocessor flags, include search hierarchies (`-I`, `-isystem`), preprocessor definitions (`-D`), and target outputs (`-o`), maps source-to-header dependencies, computes transitive reverse compilation impact graphs, and diagnoses flag regressions or optimization drift across software revisions.

## Key Features

- **Streaming Compilation Database Parser**:
  Parses multi-gigabyte `compile_commands.json` files generated by massive enterprise C/C++ codebases without excessive memory overhead.
- **Compiler Flag Normalizer & Canonicalizer**:
  Extracts flags across GCC, Clang, and MSVC dialects:
  - Include search directories (`-I`, `-isystem`, `/I`) with absolute path normalization.
  - Preprocessor macros (`-D<NAME>=<VALUE>`).
  - Optimization levels and warning flags (`-O2`, `-O3`, `-Wall`, `-Wextra`).
  - Language standards (`-std=c++20`, `-std=gnu17`).
- **Transitive Reverse Impact Analysis (`buildscope.impact/v1`)**:
  Builds a directed dependency graph linking translation units (`.cpp`, `.c`) to headers (`.h`, `.hpp`). When a header changes, `lens-build` computes the exact transitive closure of all object files that must be recompiled, predicting incremental rebuild times and caching efficiency.
- **Differential Compilation Diagnostics (`buildscope.diff/v1`)**:
  Compares two build configurations to detect:
  - Accidental loss of optimization flags (e.g. dropping `-O3` to `-O0`).
  - Added or removed macro definitions altering ABI or feature flags.
  - Newly introduced or removed translation units.

## Architecture

```
                 compile_commands.json
                           │
                           ▼
               ┌───────────────────────┐
               │    Compiler Parser    │
               │  - Includes, Defines  │
               │  - Flags, Target Obj  │
               └───────────┬───────────┘
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
  ┌───────────────────────┐   ┌───────────────────────┐
  │      ImpactGraph      │   │   diff_compilations   │
  │ (Header Reverse DAG)  │   │  - Flag Alterations   │
  │ - Transitive Impact   │   │  - Unit Adds/Removals │
  └───────────┬───────────┘   └───────────┬───────────┘
              ▼                           ▼
        ImpactReport                  BuildDiff
```

## Schemas Supported

- **Snapshot**: `buildscope.snapshot/v4`
- **Diff**: `buildscope.diff/v1`
- **Impact**: `buildscope.impact/v1`

## API Usage

```rust
use lens_build::{CompileCommandEntry, parse_command_entry, ImpactGraph, diff_compilations};

let entry = CompileCommandEntry {
    directory: "/project/build".to_string(),
    file: "/project/src/main.cpp".to_string(),
    command: None,
    arguments: Some(vec![
        "/usr/bin/c++".to_string(),
        "-std=c++20".to_string(),
        "-I/project/include".to_string(),
        "-c".to_string(),
        "/project/src/main.cpp".to_string(),
        "-o".to_string(),
        "main.o".to_string(),
    ]),
    output: None,
};

let unit = parse_command_entry(&entry);
assert_eq!(unit.standard, Some("c++20".to_string()));

// Compute rebuild impact for a header
let mut graph = ImpactGraph::new();
graph.add_unit_include("/project/src/main.cpp", "/project/include/core.h");
let report = graph.compute_impact("/project/include/core.h");
println!("Impacted units: {:?}", report.impacted_units);
```

## CLI Subcommand

```bash
# Analyze compilation database
lens build inspect compile_commands.json --output build-snapshot.json

# Calculate what files will rebuild if a header is modified
lens build impact compile_commands.json --header include/common.h

# Compare debug vs release build flags or build configuration changes
lens build diff before_compile_commands.json after_compile_commands.json
```
