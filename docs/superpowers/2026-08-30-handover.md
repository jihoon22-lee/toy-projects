## 3. 결정과 그 이유 — 다시 논의하지 말 것

**"로직은 core, Qt 는 얇은 껍데기" 원칙은 폐기됐다.** 사용자 판단이다 — Qt 는 GUI 툴킷이기
전에 프레임워크이고, 내부 개발에서는 Qt 5.15 로 core 까지 구현한다. **`README.md` 에서 그
문장을 지우는 것이 계획 Task 6 Step 3 이다.** 아직 안 지웠으므로 문서와 방침이 어긋나 있다.

계획이 `parseLines` 를 core 로 옮기는 이유는 원칙 때문이 아니라 **그것이 파서 로직이고 테스트
대상이기 때문**이다. 지금은 익명 네임스페이스라 테스트가 이름을 부를 수 없다.

**빌드 시스템이 프로젝트마다 다른 것은 의도다.** ici 에 어댑터가 둘인데 실물 프로젝트가
하나뿐이면 나머지 하나는 픽스처만으로 설계한 것이 된다. 실제로 `diskmap` 을 qmake 로 옮기고
나서야 드러난 ici 결함이 둘 있었다(§5).

**헤더는 `include/<project>/gui/`.** `include/gui/` 가 아니라 접두사를 유지한 이유는 그러지
않으면 트리에서 유일하게 접두사 없는 경로가 되어 규칙이 다시 둘이 되기 때문이다.

**`loglens` 의 커버리지 임계값이 80/90 → 55/80 으로 내려가 있다.** 코드가 나빠져서가 아니라
어댑터가 GUI 를 빌드하면서 **테스트 없는 Qt 셸 165 statements 가 분모에 들어왔기** 때문이다.
`loglens/ici.toml` 에 파일별 수치와 근거가 있다. `diskmap` 은 셸이 작아 80/90 을 그대로 두고도
통과한다. **다음 계획의 목표가 이걸 되돌리는 것이고, 실측이 못 미치면 되돌리지 못한다 —
그때는 도달값과 남은 것을 적는다. 못 올렸는데 올렸다고 적는 것이 유일한 실패다.**

## 4. 물릴 자리

**빌드 정의에 GUI 헤더를 명시적으로 나열해야 한다.** CMake `AUTOMOC` 은 `.cpp` 와 같은
디렉터리에 같은 이름인 헤더만 자동으로 찾고, qmake 는 `HEADERS` 에 적힌 것만 moc 에 넘긴다.
헤더가 `include/` 로 간 뒤로는 둘 다 자동 탐지가 끊긴다. **안 적으면 `Q_OBJECT` 클래스가
조용히 vtable 미해결로 링크 실패한다** — 어댑터로 없앤 바로 그 실패다. 위젯을 추가할 때마다
이 자리다.

**`ici verify` 가 도는 중에 그 프로젝트 파일을 편집하지 마라.** 한 번 그래서 링커 에러를
레이스로 오진했다.

**`sudo` 가 암호를 요구한다.** 패키지 설치는 사용자에게 부탁해야 한다.

## 5. 픽스처가 놓친 결함 — 이 저장소가 존재하는 이유

`diskmap` 을 qmake 로 옮기면서 ici 결함 둘이 드러났다. **ici 의 qmake 픽스처는 둘 다 통과한
상태였다.**

- **qmake 는 Qt 링크 테스트를 `target_wrapper.sh` 로 실행한다.** ici 가 그 줄을 못 읽어
  테스트 6개 중 5개만 셌다. 픽스처는 Qt 테스트가 하나뿐이라 XML 폴백이 구해줬다.
- **qmake 는 상대 경로로 컴파일한다.** `.gcov` 파일명이 `^#^#^#src#format.cpp` 가 되고 line
  커버리지가 통째로 유실됐다. **픽스처는 그 코드 경로를 실제로 지나갔는데도** 커버리지 존재
  여부만 단언하고 값을 안 봐서 통과했다.

두 번째가 교훈이다. **픽스처를 만들 때 "지나가는가" 가 아니라 "무엇을 단언하는가" 를 봐야 한다.**

전체 목록은 [`ICI-GAPS.md`](../../ICI-GAPS.md) 의 "어댑터 작업에서 새로 발견한 것" 에 있다.

## 6. 환경

WSL2 + WSLg 라 **GUI 앱이 Windows 데스크톱에 실제 창으로 뜬다.** 헤드리스로 돌릴 때만
`QT_QPA_PLATFORM=offscreen` 을 준다. `diskmap` 의 위젯 테스트는 `QWidget` 을 만들므로 검증할
때 이 변수가 필요하다.

| 도구 | 버전 | 비고 |
|---|---|---|
| cmake / ctest | 4.2.3 | |
| qmake6 | 6.10.2 | `qt6-base-dev` 와 **별도 패키지** |
| Qt6 Widgets/Concurrent/Test | 6.10.2 | |
| Qt5 | **미설치** | `qtbase5-dev 5.15.18` 로 설치 가능 |

내부망은 Qt 5.15 다. **Qt 5 와 어긋나는 소스는 두 줄뿐이다** —
`diskmap/src/gui/treemap_widget.cpp` 의 `event->position()`(Qt 6 전용, Qt 5 는 `localPos()`).
나머지는 이미 양쪽에서 컴파일된다. 계획 Task 5 가 이걸 다룬다.

Qt 5 검증을 하려면 사용자에게 부탁한다.

```bash
sudo apt-get update && sudo apt-get install -y qtbase5-dev qt5-qmake qtbase5-dev-tools
```

## 7. 실행과 검증

```bash
# 검증 (build/ici-* 는 ici 가 소유하는 shadow 트리. 이상하면 지우고 다시 돌린다)
cd loglens && QT_QPA_PLATFORM=offscreen ../../ici/dist/ici.pyz verify
cd diskmap && QT_QPA_PLATFORM=offscreen ../../ici/dist/ici.pyz verify

# 직접 빌드·테스트
cd loglens && cmake -S . -B build/check -DCMAKE_BUILD_TYPE=Debug && cmake --build build/check --parallel \
  && QT_QPA_PLATFORM=offscreen ctest --test-dir build/check --output-on-failure
cd diskmap && mkdir -p build/check && cd build/check && qmake6 ../../diskmap.pro && make -j"$(nproc)" \
  && QT_QPA_PLATFORM=offscreen make check TESTARGS=-xunitxml
```

GUI 는 Release 로 빌드해 두었다.

```bash
./loglens/build/release/src/gui/loglens-gui /tmp/live.log
./diskmap/build/release/src/gui/diskmap-gui ~/projects
```

`/tmp/feed-log.sh` 가 1초에 한 줄씩 `/tmp/live.log` 에 추가해 팔로우를 볼 수 있게 해준다.
`: > /tmp/live.log` 로 비우면 로테이션 처리(모델 리셋)가 보인다. **둘 다 임시 파일이라
재부팅하면 사라진다** — `loglens/tests/data/sample.log` 로 다시 만들면 된다.
