**L2 bounded foundation 및 background loader 현재 상태 (2026-08-31).** 기본 8,192-record
stable-ID ring을 CLI/GUI에 연결하고, 1 MiB source chunk, fixed one-shot snapshot, 64 KiB
pathological record cap과 exact omission metadata를 유지한다. 초기 GUI 로드는 `Latest
records`(Tail N)와 `From start` 중에서 고를 수 있다. Tail N은 continuation을 포함한
logical record root를 byte scan으로 찾아 선택된 offset에서 parser를 시작하므로 원래
physical line number를 보존한다. 두 모드는 source identity와 snapshot boundary를 확인해
선택 시점과 실제 로드 시점이 달라진 파일의 bytes를 합치지 않는다.

`LogLoadWorker`는 `FileTailer`와 `RecordAssembler`를 전용 `QThread`에서 소유하고, GUI
thread에는 최대 512개의 `RecordDelta`를 담은 `LoadBatch`만 보낸다. GUI가 동일한 `job_id`와
`sequence`를 acknowledge하기 전에는 worker가 다음 chunk/batch를 읽거나 발행하지 않는다.
새 job 선택은 thread-safe cancellation gate로 이전 job을 취소하며, GUI는 stale job과 sequence
mismatch를 적용하지 않는다. Follow 중지/취소는 pending poll을 폐기하고, 다시 켜면 현재
generation에서 재개한다. structured filter와 대소문자 구분 없는 search는 background load
중에도 GUI thread에서 안전하게 바꿀 수 있고 timeline 갱신은 debounce된다.

이 변경의 로컬 native 증거는 Qt 5.15.18과 Qt 6.10.2에서 각각 전체 CTest 12/12 PASS이며,
Qt 6 strict `-Wall -Wextra -Wpedantic -Werror` 빌드와 CTest도 12/12 PASS다. worker 전용
QtTest는 QSignalSpy/QTRY 및 blocking queued 경계로 고정 sleep 없이 ACK backpressure, stale
job, Tail N line number, invalid source와 rotation을 검증한다. 구현 head `e19fea9`의 ici
deep no-cache local verify도 Suite PASS, 11 pass / 0 warn / 0 fail / 0 error / 2 skip,
TEM 4.83, line/function/branch 93.4%/96.6%/81.6%, maximum complexity 15(0 issues),
duplication 1.72%, sanitizer PASS, HTML 428,025 bytes·external refs 0개였다.

**L2 대용량 benchmark 결정 (2026-08-31).** canonical input은 정확히 1,073,741,824 bytes,

## 3. 결정과 그 이유 — 다시 논의하지 말 것

**"로직은 core, Qt 는 얇은 껍데기" 원칙은 폐기됐다.** 사용자 판단이다 — Qt 는 GUI 툴킷이기
전에 프레임워크이고, 내부 개발에서는 Qt 5.15 로 core 까지 구현한다. **`README.md` 에서 그
문장을 제거하고, CLI와 GUI가 같은 핵심 의미론을 공유한다는 현재 규칙으로 정리했다. Qt를
core에서 금지하지 않는다는 원칙과 Qt 5/Qt 6의 실제 지원 완료는 별개였으며, T0-5에서
양쪽 build/test/smoke 증거를 확보해 완료로 표시했다.

계획이 `parseLines` 를 core 로 옮기는 이유는 원칙 때문이 아니라 **그것이 파서 로직이고 테스트
대상이기 때문**이다. 지금은 익명 네임스페이스라 테스트가 이름을 부를 수 없다.

**빌드 시스템이 프로젝트마다 다른 것은 의도다.** ici 에 어댑터가 둘인데 실물 프로젝트가
하나뿐이면 나머지 하나는 픽스처만으로 설계한 것이 된다. 실제로 `diskmap` 을 qmake 로 옮기고
나서야 드러난 ici 결함이 둘 있었다(§5).

**헤더는 `include/<project>/gui/`.** `include/gui/` 가 아니라 접두사를 유지한 이유는 그러지
않으면 트리에서 유일하게 접두사 없는 경로가 되어 규칙이 다시 둘이 되기 때문이다.

**`loglens` 의 커버리지 임계값은 branch 75/function 92로 상향됐다.** GUI 셸을 포함한 ici
0.6.0 실측이 line 93.2%, function 96.9%, branch 81.8%, TEM 4.84였고, 남은 QPainter/Qt
내부 예외 경로에 합리적 slack을 둔 값이다. `loglens/ici.toml` 에 파일별 수치와 근거가 있다.
`diskmap` 은 셸이 작아 80/90 을 그대로 두고도 통과한다. **수치에 맞춰 임계값을 낮추지 않고
검증 가능한 application state를 우선 게이트한다.**

**D1 Slice 2의 storage 의미론은 확정값만 확정값으로 표시한다.** logical size는 entry마다
세지만 allocated size는 유효한 physical identity마다 한 번만 세며, reclaimable size는
subtree가 known hard-link reference를 모두 소유할 때만 known이다. symlink target alias는
소유 reference가 아니고, incomplete/unknown metadata는 `*_known=false`로 전파한다. finite
`max_depth`로 잘린 directory도 `complete=false`와 `scan depth limit reached`를 남겨
allocated/reclaimable total을 unknown으로 만든다. logical aggregate는 별도 known bit가
없으므로 `uint64_t` overflow에서 최댓값으로 포화한다. followed directory의 target identity가
없으면 확장을 계속하지 않고 incomplete 오류를 남긴다. 이 규칙은 D2의 cancellation/rescan과
D4의 cleanup revalidation이 재사용할 기반 계약이다. 후속 `6861b7a`/`2f56caf`는 regular-file
root를 complete한 one-node scan으로 반환하고, 명시적으로 선택한 root symlink를 항상
dereference하도록 했다. symlink-to-file은 leaf이며 broken target 오류는
`ScanResult.errors`에도 포함된다. root symlink dereference와 descendant follow 설정은 서로
독립이다.

## 4. 물릴 자리

**빌드 정의에 GUI 헤더를 명시적으로 나열해야 한다.** CMake `AUTOMOC` 은 `.cpp` 와 같은
디렉터리에 같은 이름인 헤더만 자동으로 찾고, qmake 는 `HEADERS` 에 적힌 것만 moc 에 넘긴다.
헤더가 `include/` 로 간 뒤로는 둘 다 자동 탐지가 끊긴다. **안 적으면 `Q_OBJECT` 클래스가
조용히 vtable 미해결로 링크 실패한다** — 어댑터로 없앤 바로 그 실패다. 위젯을 추가할 때마다
이 자리다.

**`ici verify` 가 도는 중에 그 프로젝트 파일을 편집하지 마라.** 한 번 그래서 링커 에러를
레이스로 오진했다.

**`sudo` 가 암호를 요구한다.** 패키지 설치는 사용자에게 부탁해야 한다.

## 5. 픽스처가 놓친 결함 — 이 저장소가 존재하는 이유

`diskmap` 을 qmake 로 옮기고 D1 coverage를 반복하면서 ici 결함 셋이 드러났다. **기존 ici
qmake 픽스처는 모두 통과한
상태였다.**

- **qmake 는 Qt 링크 테스트를 `target_wrapper.sh` 로 실행한다.** ici 가 그 줄을 못 읽어
  테스트 6개 중 5개만 셌다. 픽스처는 Qt 테스트가 하나뿐이라 XML 폴백이 구해줬다.
- **qmake 는 상대 경로로 컴파일한다.** `.gcov` 파일명이 `^#^#^#src#format.cpp` 가 되고 line
  커버리지가 통째로 유실됐다. **픽스처는 그 코드 경로를 실제로 지나갔는데도** 커버리지 존재
  여부만 단언하고 값을 안 봐서 통과했다.
- **재사용 shadow의 static consumer가 stale archive를 계속 링크할 수 있다.** `.gcda`와
  `.gcno` stamp 불일치가 scanner coverage를 0%로 만들었다. DiskMap의 `PRE_TARGETDEPS`와 ici
  [#94](https://github.com/jihoon22-lee/ici/pull/94)의 qmake `make clean` freshness step이
  각각 project graph와 adapter 경계를 보강했고, candidate 실측에서 test/sanitize 양쪽 clean
  evidence와 Suite PASS를 확인했다.

공통 교훈은 **픽스처를 만들 때 "지나가는가" 가 아니라 "무엇을 단언하는가" 를 봐야 한다**는
것이다.

전체 목록은 [`ICI-GAPS.md`](../../ICI-GAPS.md) 의 "어댑터 작업에서 새로 발견한 것" 에 있다.

| qmake / Qt5 Core/Widgets/Concurrent/Test | 5.15.18 | `/usr/bin/qmake`, 현재 설치됨 |

Qt 5 CMake 검증은 `-DCMAKE_DISABLE_FIND_PACKAGE_Qt6=ON`, Qt 6 검증은
`-DCMAKE_DISABLE_FIND_PACKAGE_Qt5=ON`으로 반대 major 탐색을 막고 configure log와 link target을
확인한다. qmake는 `/usr/bin/qmake`/`/usr/bin/qmake6`와 `-query QT_VERSION`을 사용한다.
`CMAKE_PREFIX_PATH`만 주는 것은 Qt 5 강제가 아니다.

현재 background loader slice의 native 확인 명령은 다음과 같다. 각 CMake shadow는 반대 Qt
major 탐색을 막아 선택한 toolchain을 증명하고, 마지막 명령은 같은 source에서 엄격 경고를
게이트한다.

```bash
cd loglens
cmake -S . -B build/loglens-qt6 -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_DISABLE_FIND_PACKAGE_Qt5=ON
cmake --build build/loglens-qt6 --parallel
QT_QPA_PLATFORM=offscreen ctest --test-dir build/loglens-qt6 --output-on-failure

cmake -S . -B build/loglens-qt5 -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_DISABLE_FIND_PACKAGE_Qt6=ON
cmake --build build/loglens-qt5 --parallel
QT_QPA_PLATFORM=offscreen ctest --test-dir build/loglens-qt5 --output-on-failure

cmake -S . -B build/loglens-qt6-strict -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_DISABLE_FIND_PACKAGE_Qt5=ON \
  -DCMAKE_CXX_FLAGS="-Wall -Wextra -Wpedantic -Werror"
cmake --build build/loglens-qt6-strict --parallel
QT_QPA_PLATFORM=offscreen ctest --test-dir build/loglens-qt6-strict --output-on-failure
```

기록된 L2 benchmark의 로컬 결과는 Qt 5.15.18, Qt 6.10.2 각각 12/12 CTest PASS이고
Qt 6 strict benchmark build도 PASS다. 당시 ici 0.6.0 deep no-cache는 Suite PASS, 12/12 tests,
TEM 4.83, line/function/branch 93.6%/96.6%/81.8%, maximum complexity 15, duplication 1.71%,
sanitizer PASS, HTML 433,351 bytes·external refs 0개였다. background/Tail N의 원격 증거는
위 PR #25에서 닫혔고, L2 benchmark는 PR #26의 squash merge, green PR gate, sticky comment와
Pages 검증, main Qt5/Qt6 full sweep까지 완료했다.

## 7. 실행과 검증

```bash
# 검증 (build/ici-* 는 ici 가 소유하는 shadow 트리. 이상하면 지우고 다시 돌린다)
cd loglens && QT_QPA_PLATFORM=offscreen ../../ici/dist/ici.pyz verify
cd diskmap && QT_QPA_PLATFORM=offscreen ../../ici/dist/ici.pyz verify

# 설치된 두 Qt major 확인
qmake -v       # Qt 5.15.18
qmake6 -v      # Qt 6.10.2
pkg-config --modversion Qt5Core Qt5Widgets Qt5Concurrent Qt5Test
pkg-config --modversion Qt6Core Qt6Widgets Qt6Concurrent Qt6Test

# 직접 빌드·테스트
cd loglens && cmake -S . -B build/check -DCMAKE_BUILD_TYPE=Debug && cmake --build build/check --parallel \
  && QT_QPA_PLATFORM=offscreen ctest --test-dir build/check --output-on-failure
cd diskmap && mkdir -p build/check && cd build/check && qmake6 ../../diskmap.pro && make -j"$(nproc)" \
  && QT_QPA_PLATFORM=offscreen make check TESTARGS=-xunitxml
```

GUI 는 Release 로 빌드해 두었다.

```bash
./loglens/build/release/src/gui/loglens-gui /tmp/live.log
./diskmap/build/release/src/gui/diskmap-gui ~/projects
```

`/tmp/feed-log.sh` 가 1초에 한 줄씩 `/tmp/live.log` 에 추가해 팔로우를 볼 수 있게 해준다.
`: > /tmp/live.log` 로 비우면 로테이션 처리(모델 리셋)가 보인다. **둘 다 임시 파일이라
재부팅하면 사라진다** — `loglens/tests/data/sample.log` 로 다시 만들면 된다.
