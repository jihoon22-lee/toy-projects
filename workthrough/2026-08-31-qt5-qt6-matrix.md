# Qt5/Qt6 GUI matrix and manifest expansion

## Overview

T0-5의 공통 Qt version 계약을 CI에 연결했다. GUI project manifest 한 항목이 discovery에서
Qt5·Qt6 두 leg로 확장되고, 현재 `diskmap`과 `loglens`는 네 개의 독립 job에서 선택 major의
toolchain, pkg-config metadata, native tests, 실제 headless GUI 실행까지 검증한다.

## Context

기존 `gui-build`는 모든 프로젝트를 Qt6으로만 빌드했고, manifest discovery도 프로젝트당 한
항목만 내보냈다. qmake의 실제 executable/test 경로와 CMake가 선택한 Qt major를 CI가
확인하지 않아, 설치된 다른 major에서만 깨지는 회귀를 merge gate가 놓칠 수 있었다.
`report-pr`는 PR source를 checkout하지 않고 release ici와 verify artifact만 처리하는 기존
write 권한 경계를 유지해야 했다.

## Changes Made

### 1. Manifest/discovery contract

- `ci/check_manifest.py`
  - `SUPPORTED_QT_MAJORS = (5, 6)`을 단일 source of truth로 추가했다.
  - enabled GUI entry마다 `qt_major`가 붙은 두 matrix object를 생성한다.
  - 테스트 가능한 `root` 인자를 추가했지만 workflow의 기본 repository-relative 동작은
    그대로 유지한다.
- `ci/test_check_manifest.py`
  - 현재 두 프로젝트가 정확히 `(diskmap,5)`, `(diskmap,6)`, `(loglens,5)`,
    `(loglens,6)`으로 확장되는지 확인한다.
  - 임시 stdlib fixture에 새 CMake GUI project를 만들고 같은 양 major 확장이 자동 적용되는지
    확인한다.

### 2. Four-leg Qt GUI workflow

- `.github/workflows/ci.yml`
  - job 이름에 `Qt${{ matrix.project.qt_major }}`를 표시한다.
  - Qt5는 `qtbase5-dev`, `qt5-qmake`, Qt6은 `qt6-base-dev`, `qmake6`를 조건부 설치한다.
  - 선택 major의 `Qt{5,6}Core/Gui/Widgets/Concurrent/Test` pkg-config version을 출력하고
    major prefix를 검증한다.
  - CMake는 Qt5 leg에서 `CMAKE_DISABLE_FIND_PACKAGE_Qt6=ON`, Qt6 leg에서
    `CMAKE_DISABLE_FIND_PACKAGE_Qt5=ON`을 전달하고 configure output을 확인한다.
  - qmake는 Qt6에 `/usr/bin/qmake6`, Qt5에 `/usr/bin/qmake`를 사용하고 `-query QT_VERSION`
    결과를 확인한다.
  - 모든 GUI binary의 `ldd`에서 선택 major `libQt{5,6}Widgets` 링크를 확인한다.
  - CMake는 CTest, qmake는 `make check`, 양쪽 모두 offscreen 실제 GUI smoke를 실행한다.
  - action pin, report-pr 구조, top-level read-only permission과 report-pr의 write 권한 분리는
    변경하지 않았다.

```yaml
# .github/workflows/ci.yml (selection contract)
name: Qt${{ matrix.project.qt_major }} GUI build (${{ matrix.project.name }})
...
case "$QT_MAJOR" in
  5) qt_guard=-DCMAKE_DISABLE_FIND_PACKAGE_Qt6=ON ;;
  6) qt_guard=-DCMAKE_DISABLE_FIND_PACKAGE_Qt5=ON ;;
esac
cmake -S . -B build/gui "$qt_guard"
```

### 3. Build metadata and documentation

- `loglens/CMakeLists.txt`는 어느 major가 disable됐든 해당 이름을 `REQUIRED NAMES`에서
  제거하여 명시적 반대-major 검증을 실제로 적용한다.
- `diskmap/ici.toml`의 scope를
  `Qt6Widgets`, `Qt6Concurrent`, `Qt5Widgets`, `Qt5Concurrent` 순서로 확장했다.
- `README.md`, `ROADMAP.md`, master plan과 Qt shell 상세 plan에 네-leg 계약, 선택 증거,
  native test/smoke 결과와 원격 CI 재검증 조건을 기록했다.

### Local Qt matrix

| Project | Qt5 | Qt6 |
|---|---|---|
| loglens / CMake | `Qt5 5.15.18`, CTest 10/10, linked `libQt5Widgets`, smoke PASS | `Qt6 6.10.2`, CTest 10/10, linked `libQt6Widgets`, smoke PASS |
| diskmap / qmake | `/usr/bin/qmake` `5.15.18`, `make check`, linked `libQt5Widgets`, smoke PASS | `/usr/bin/qmake6` `6.10.2`, `make check`, linked `libQt6Widgets`, smoke PASS |

qmake의 QtTest output은 각 major에서 `test_treemap_widget` 6/6, `test_main_window` 6/6을
보고했고, core test들도 모두 `All checks passed`를 보고했다. CMake configure output은
각각 `loglens: using Qt5 5.15.18`과 `loglens: using Qt6 6.10.2`를 보고했다.

## Next Steps

- PR에서는 GitHub Actions 네 GUI matrix와 Merge Gate를 실행하고, 기존 report-pr가 모든
  verify artifact를 모아 HTML 링크를 sticky comment에 추가하는지 확인한다.
- 새 프로젝트는 `ci/projects.json`의 GUI metadata와 `ici.toml`만 추가하면 discovery가
  Qt5·Qt6 두 leg를 자동 생성한다. CMake 프로젝트는 configure output에 선택 major를
  명시하는 convention을 따라야 한다.
