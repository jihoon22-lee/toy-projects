# 2026-10-03 — v0.1.1 코드 리뷰 지적 사항 수정 (v0.1.2)

> **역사적 작업 기록** — 아래 기능 범위, 계획, 테스트 수, 버전 및 Git/배포 상태는
> 해당 작업 단계에서 기록한 내용이다. 현재 사용법이나 최신 검증·배포 상태를 뜻하지 않는다.
> 현재 제품별 안내는 [저장소 README](../README.md), 변경 이력은
> [CHANGELOG](../CHANGELOG.md), 후속 계획은 [ROADMAP](../ROADMAP.md)을 참고한다.

## 배경

v0.1.1로 릴리스된 2·3차 기능 라운드(#104–#115)를 상세 리뷰해 15건을 찾았고,
이 기록의 대상인 당시 15건을 전부 수정했다. 제품별 커밋으로 나눠 release-please가 제품별 CHANGELOG를
정확히 만들도록 했다.

## 수정 내역

| # | 제품 | 문제 | 수정 |
|---|------|------|------|
| 1 | loglens | 플러그인 정규식(`std::regex_match`)이 줄 길이에 비례해 재귀 → 기본 64 KiB 레코드에서 `(.*)`만으로 SIGSEGV | libstdc++ 비재귀(BFS) 실행기 사용, 그 외 표준 라이브러리는 2 KiB 초과 줄을 매칭하지 않음, `regex_error`는 Unstructured + 진단 |
| 2 | loglens GUI | 세션의 level과 filter를 문자열로 이어 붙여 `OR` 우선순위가 바뀜 | `level>=X AND (filter)`로 괄호 처리 |
| 3 | loglens GUI | 필터 없는 세션을 열면 이전 필터가 남음 | 빈 필터도 항상 적용해 초기화 |
| 4 | loglens GUI | 세션 저장 대화상자 기본 경로가 열린 로그 파일 자체 | `<log>.session.json` 제안, 열린 로그 경로로의 저장 거부 |
| 5 | envlens | `Requires-External`이 있으면 동일 스냅샷 diff·check가 항상 `unknown`/exit 1 | baseline에 이미 있던 external requirement는 상태에 영향 없음, 새로 생긴 것만 `unknown` |
| 6 | envlens | `check` 리포트가 "envlens diff" 헤더와 diff 요약으로 출력 | 전용 text/Markdown 렌더러, 요약은 증거 키만, 자기 자신과의 diff 대신 직접 계산 |
| 7 | buildscope | 스트리밍 파서가 UTF-8 BOM이 붙은 DB를 거부 (회귀) | BOM 건너뜀, 배열이 아닌 루트는 기존의 정확한 파싱 오류 메시지 유지, 빈 요소(`[,]`) 명시적 거부 |
| 8 | abilens | `forbid_stripped`가 stripped 여부를 모르면 통과 | fail-closed 위반 처리 |
| 9 | abilens | 심볼 규칙이 `name@version`과 정확히 일치해야만 매칭 | `@` 없는 규칙은 모든 버전에 매칭, `@` 있는 규칙은 정확히 매칭 |
| 10 | abilens | 0.1.1 이전 리포트와 diff 시 모든 버전 심볼·vtable이 변경으로 표시 | `symbols_known`/`vtables_known` 추적, 구 리포트는 이름 기준 비교·vtable 축 생략 + 진단 |
| 11 | abilens | `DT_VERDEF`/`DT_VERSYM` 손상 시 바이너리 전체가 Corrupt | 비한정 심볼로 강등 + `symbol versions unavailable` 진단 |
| 12 | loglens | `--format-plugin`이 세션에 저장되지 않고 `--format`을 조용히 덮어씀 | 세션 `source.format_plugin` 필드(설정 시에만 기록), 두 옵션 동시 사용은 오류 |
| 13 | loglens | 캡처 그룹 번호 `2.9`·`1e1`이 잘려서 수용됨 | 전체 토큰이 정수일 때만 허용 |
| 14 | loglens | GUI 세션 테스트가 버튼 존재만 확인 | `openSession`/`saveSessionTo`로 분리하고 동작 테스트 추가 |
| 15 | diskmap | 도달 불가능한 `--compare-snapshot` 검증 분기 | 제거 (사용자 영향 없음) |

## 당시 검증

- 각 제품 CI 게이트를 로컬에서 동일하게 실행: loglens/diskmap/buildscope `ctest`
  (offscreen), abilens `make all test`, envlens pytest + ruff check/format +
  mypy `--strict` (Python 3.10).
- 새 테스트가 실제로 결함을 잡는지 확인: 수정 전 소스로 되돌리거나 수정을
  하나씩 원래대로 바꾼(mutation) 상태에서 해당 테스트가 실패함을 확인.
- 정규식 크래시 임계값 측정(8 MiB 스택): `(.*)`는 64 KiB, `((\w|\s|-|:)+)`는
  16 KiB에서 SIGSEGV. BFS 실행기는 1 MiB 줄을 약 0.1초에 처리하고 캡처 결과는
  기존 실행기와 동일.

## 당시 릴리스 결과

- abilens, buildscope, envlens, loglens → `v0.1.2` (`fix` 커밋).
- diskmap은 사용자 영향 없는 `refactor`만 있어 `v0.1.1` 유지.


이 표는 v0.1.2 작업 당시의 변경 설명이다. 이후의 세션 스키마, ABI 판정,
저장 경로 보호 및 기타 지원 범위를 제한하는 현재 사양으로 읽지 않는다.
최신 계약은 [LogLens](../loglens/README.md), [EnvLens](../envlens/README.md),
[BuildScope](../buildscope/README.md), [AbiLens](../abilens/README.md),
[DiskMap](../diskmap/README.md)의 제품 안내를 따른다.
